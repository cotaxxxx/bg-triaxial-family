## 読み方と、移す範囲の決定

1. 格子がある状態の包囲では、配列の演算が 81〜87% を占める。`fsum` は 1% に満たない。制御は 13〜19% だが、その大半は、演算 1 つごとに Python の関数を 1 回呼ぶ手間であり、配列の演算を C に移せば一緒に消える。
2. したがって、移す対象は**被積分関数の評価**（区間・双対数・ジェットの演算の列）とした。`fsum` と `_mv_cells` は、時間の上では移す理由が小さい。C 版での残りの時間は報告の §5 に示す。
3. 格子を空から作る時間は、包囲 1 回と同じかそれより長い（N = 256 で 10〜12 秒）。格子は置き場に残るので、同じ格子を使い回せる間は効かない。使い回せないとき（grade ≠ 0 の格子は、箱の q₃ の中心ごとに別のものになる）には、これが残る。格子の生成は mpmath の 40 桁の計算で、今回は移していない。C へ渡す配列の形は、Reader が持っている形のまま（N × 2N の binary64 の配列を、下端と上端で 1 組ずつ）である。
