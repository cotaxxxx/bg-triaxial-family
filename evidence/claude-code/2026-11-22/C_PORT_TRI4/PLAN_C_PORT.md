## 1. 作り（何を C に移すか）

### 1.1 方式

被積分関数の式を人の手で C に書き写すことはしない。次の方式を取る。

- `src/_tape.py`：`tri4._make` と `tri3._make` が返す被積分関数を包む。ある形の引数で初めて呼ばれたとき、**元の Python の関数をそのまま** 1 回、記号的な区間（`fiv.I` の子クラス）で走らせ、行われた区間演算を順に記録する（テープ）。記録されるのは、加、減、符号反転、乗、除、二乗、平方根、切り詰め（`clip`）と、被積分関数が端点を直接組み立てる 3 つの操作である。
- `src/tape_kernel.c`：テープを、セル 128 個ずつ再生する。演算ごとに、`fiv.py` と同じ式（最近接丸めの四則・平方根のあと、下端は 1 つ下、上端は 1 つ上の binary64 へ）を行う。

この方式を取る理由は、指示書 §3 作業 2 の「式を写す規則」（0 を足す・1 を掛けるを省かない、左からの順序、`2*a` や `int*I` の変換、`None` の成分を飛ばす所）を、人の注意力ではなく仕組みで守るためである。演算の列は元のコードが行ったとおりに記録されるので、整理も並べ替えも起こらない。`dual.py`、`jet.py`、`tri*.py`、PQF の級数は 1 文字も書き換えない。

配列全体にかかる条件（0 を含む区間での割り算、負の数の平方根）は、C の側で全セルについて調べ、`fiv.py` が `ValueError` を出すはずの最初の演算で、同じ `ValueError` を出す。

記録の途中で、知らない操作か、値による分岐に出会ったら、記録をやめ、その呼び出しは元の Python の関数で計算する。その回数を数えて記録する（下の条件 A-3）。

### 1.2 移す範囲と、移さない範囲

| 部分 | この版 |
|---|---|
| 格子の上の被積分関数の評価（区間・双対数・ジェット） | **C**（テープ） |
| `_mv_cells`（角度の平均値の組み立て） | Python のまま |
| `fsum` | Python のまま（`math.fsum` そのもの） |
| 格子の生成（mpmath） | Python のまま |
| `tri4.enclose` の組み立て、`enclose.last` | Python のまま（指示書どおり） |

指示書は「`_mv_cells`、`fsum` まで」を対象としている。この版ではその 2 つを移さない。理由は、(1) `math.fsum` をそのまま使えば、和の 1 ビット一致は試験するまでもなく成り立つこと、(2) 移す範囲は作業 1 の表で決めるという指示であること、である。作業 1 の表と、C 版での残りの時間・最大メモリを報告に書き、この 2 つを移す利点があるかどうかを数字で示す。移す案は、実装せずに報告の中で提案として書く。

### 1.3 SIMD と最適化の水準

指示書は `-O2` までとしている。`-O2` では GCC はこのループを自動ではベクトル化しない（測った）。そこで、内側のループを AVX2 の組み込み関数で手で書いた。使うのは、IEEE の加減乗除と平方根、`MINPD`／`MAXPD`（C の `a<b?a:b`、`a>b?a:b` と同じ意味）、比較、符号化された整数の演算だけである。FMA の命令は書いていないし、`-ffp-contract=off` で縮約も禁じる。`-mavx2` を付けずにコンパイルすると、同じソースがスカラーの経路だけになり、同じ結果を出す（試験 E）。ブロックの端の 1〜3 セルは、AVX2 版でもスカラーの経路が計算する（試験 D）。

### 1.4 ビルド

```
gcc -std=c11 -O2 -ffp-contract=off -fno-fast-math -mavx2 -fPIC -shared src/tape_kernel.c -lm -o geoenclosereader/libtape.so
```

`src/build.sh` が、元の `GER2` の木を写し、上の命令で `libtape.so` を作り、`_tape.py` を置き、`geoenclosereader/__init__.py` の末尾に 2 行（包みを入れる呼び出し）を足す。元の木は読むだけである。出来た `.so` に FMA の命令（`vfmadd` など）が 1 つでもあれば、ビルドを失敗にする。

- この試験の機械：x86-64、Intel Xeon 2.1 GHz（4 コア）、Linux、GCC 13.3.0、CPython 3.13.18、NumPy 2.5.3、mpmath 1.4.1（研究用 PC に合わせ、`PYTHONPATH` で指定する）。
- 研究用 PC（V61 の結果の `env.txt` による）：AMD Ryzen 9 9900X（AVX2 あり）、Linux 7.0.0-38-generic、CPython 3.11.16（GCC 15.2.0 でビルドされたもの）、NumPy 2.4.6、mpmath 1.4.1。C コンパイラの版は私には分からない。研究用 PC では `build.sh` が版とフラグを `BUILD_INFO.txt` に書き出す。フラグは上のとおりで、変えない。
- **私は研究用 PC を使わない。** 以下の試験はすべてこの試験の機械で流す。研究用 PC での一致は、同じ試験を研究用 PC で流して確かめる必要がある（そのための手順は報告に書く）。

## 3. 試験

Python 版と C 版は、同じ機械・同じ Python・同じ NumPy・同じ mpmath で流す。スレッドは 1 本。

| 群 | 中身 | 件数 |

箱は `tests/select_cases.py`（A1、A2、A4）が作り、`tests/cases_A.json` に置いた。子の箱は、変数と半分を種つきの乱数で選んで二等分を繰り返したもので、ランナーの判定で球の外になる半分は取らない。

記録（`tests/run_cases.py`）：区間の両端の 64 ビット、`enclose.last` の全項目（`order`、`used`、`lazy_skip`、`contact_cells`、`terms`、`angular_width`、`total_width`、`p0`、`B`、`C`、`width1`、`width2`。浮動小数はビットで）、例外なら種類と文面。C 版ではさらに、C の核を呼んだ回数と、Python の関数に戻った回数。

合格の条件（3 つとも）：

- **A-1**　228 件すべてで、時間・メモリ・核の呼び出し回数を除く全項目が Python 版と同じ。
- **A-2**　次の分岐が、228 件の中にそれぞれ 1 回以上現れる：接触セルあり／接触セルなしで粗い格子のために二次の形をやめる／lazy で二次の形を省く／展開点を引き寄せる／箱が球と交わらない例外／動く変数のない箱／grade ≠ 0／E3、T12、H33 の 3 種類。
- **A-3**　C 版で、Python の関数に戻った回数が 0。

### 試験 B：木の一致（2 組）

`rep.json` の 2 組を、V61 のランナー（書き換えなし）と V61 の設定（N の上限 256、NH = max(16, N/2)、lazy あり、予算 20000 秒）で、C 版と Python 版の両方で流す。

合格の条件：2 組とも、C 版の `leaf_sha256`、葉の数（`leaves`）、評価回数（`evals`）が、chat の記録（`lazy_0.jsonl`、`lazy_1.jsonl`）と同じ。あわせて、この機械で流した Python 版とも同じ（`status`、`used2`、`lazy_skips`、`maxdepth`、`min_leaf_lo` も比べる）。

### 試験 C：自己試験（6 本）

`selftest_tri`、`selftest_tri2`、`selftest_tri3`、`selftest_tri4`、`selftest_lazy`、`examples/selftest_examples` を C 版の木で流す。

合格の条件：6 本とも `FAILURES 0`。あわせて、時間の数字を除いた出力が Python 版と同じかどうかを報告する。

### 試験 D（足した試験）：ブロックの端

本物の格子のセルの数は 128 の倍数なので、ブロックの端（4 の倍数でないセル数）を計算するスカラーの経路が、試験 A〜C では通らない。`tests/test_blocks.py` は、格子を (1,3)、(3,5)、(5,7)、(9,15)、(11,13)、(16,31)、(16,32) などの形に切り、`tri4.enclose` が使う 6 通りの呼び方（区間、角度の双対数、パラメータの双対数 2 通り、ジェット 2 通り）で、C の核と元の Python の関数の出力の全配列をビットで比べる。

合格の条件：AVX2 版とスカラー版の両方で、不一致 0。（1 セルだけの格子は、作りの上で Python の関数に戻る。その回数も記録する。）

### 試験 E（足した試験）：スカラー版

`-mavx2` なしでビルドした木で、A3 と A4 の 151 件を流す。合格の条件：全項目が Python 版と同じ。

### 全体の合否

A-1、A-2、A-3、B、C、D、E のすべてを満たすとき、この機械での等価性の試験を「合格」と書く。1 つでも満たさなければ「不合格」と書き、違った箱・N・両方の値を全部書く。合否は、この機械・このビルドについての事実であり、採否ではない。
