## 1. 背景

V62 で、赤道セル (27,7,0) の H33 は 72 点すべてで 1.15 以上と分かった（0 ではない、点の分解能でもない）。予算切れの原因は、箱の包囲でパラメータ方向の項が値より大きいことだと見ている。これを確かめる。

- 予算：各 1,800 秒（chat の作業機、2 プロセス）。木の最初の部分を、V61 と同じ順で辿る。

## 3. 集計（結果を見る前に固定）

1. 分割した次元の内訳（s、t、q₁、q₂、q₃ のどれが何回）。
2. 評価ごとに、最大の項の次元と、その項と角度の幅と |包囲の中心| の比。
3. 深さごとに、各次元の最大の項の中央値。分割で項が半分（一次）か 4 分の 1（二次）に減っているか。
4. N を 2 倍にした回数と、そのとき角度の幅がどれだけ減ったか。
5. 二次の形を使った割合。

## 4. 読み方

- 最大の項がいつも同じ次元で、分けても減り方が遅い → その次元の表示を改める（変数の取り直し、その方向の解析的な評価）。
- 項が分けるたびに減っているのに終わらない → 木が広がりすぎている（分け方の順序の問題）。
- 角度の幅が最大 → N の上限か、角度の表示の問題。
