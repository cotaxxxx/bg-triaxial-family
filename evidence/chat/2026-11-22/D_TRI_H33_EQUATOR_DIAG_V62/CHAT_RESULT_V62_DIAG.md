## 3. 判定（計画 §3 のとおり）

- **72 点すべてで、包囲の下端が正だった。** H33 はこれらの点で 1.15 以上あり、0 から遠い。セルの中での変化も 0.1 以下で、なめらかである。
- したがって、**原因 (i)「H33 がこのセルで 0 になる」は、調べた点では支持されない。** 点の間で 0 になることは、点の値だけでは否定できないが、値の大きさと変化の小ささからは考えにくい。
- **原因 (ii)「点の分解能の限界」も主因ではない。** 細長いタイル (3,7) でも、点の値 1.33 以上に対して、N = 256 での点の幅は約 0.43 で、点なら符号は決まる。
- 対照のセル (10,0,0) の値は 1.98 で、このセルの値（1.16〜1.89）と同じ大きさである。値が小さいから覆えないのではない。

## 4. 分かったこと

予算切れの原因は、値が 0 に近いことでも、点の分解能でもない。残っている可能性が高いのは、**箱の包囲で、パラメータ方向（s、t、q）の項が値より大きくなること**である。V59-B で、費用の主因として見つけたものと同じ種類である。H33 は、細長いタイルほど点の幅が大きく（(0,0) の 0.007 から (3,7) の 0.113 まで）、パラメータに対して急に変わる成分を持つと考えられる。

これは推測であり、確かめるには、止まった箱で `tri4.enclose.last` の項の内訳（角度の幅、各パラメータの項、一次と二次の形の幅）を記録する必要がある。
