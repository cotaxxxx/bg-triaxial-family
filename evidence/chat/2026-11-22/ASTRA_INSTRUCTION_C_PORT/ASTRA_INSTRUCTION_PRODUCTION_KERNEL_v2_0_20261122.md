## 1. 目的

三軸楕円体の層 I・II（停留点が赤道面の外と、赤道面の中の軸の外にないこと）を、主矩形 R = [1, 16/5] × [1, 6] の全域で、保証付きの区間で示すための本計算の核を書いてください。

V61 までの測定では、chat の Reader（Python）で全域を流すと少なくとも 22.65 CPU 年かかります。研究 PC で一か月ほどに収めるには、**Reader の Python 版の 20 倍以上の速さ**が要ります。

## 2. 決める量（定義はここから取る）

L = diag(1, s, st)、エネルギー E(q) = ⟨k arccos²γ⟩（単位球面上の平均）。式の出典は、`bg-triaxial-family` の main 枝の `evidence/source-snapshots/basepoint-v56-independent-map/REPORT.md` §1（勾配の式、境界への延長、補題 0）と、V58 の計画（`evidence/chat-originals/2026-11-20/D_TRI_LAYER_I_II_CALIBRATION_V58/chat_checks/PLAN_V58.md`）。

| 層 | 量 | 示すこと |
|---|---|---|
| I | W₃ = E₃/q₃（q₃ > 0） | W₃ > 0。赤道面の外に停留点がない |
| I（赤道の帯） | H₃₃ = ∂²E/∂q₃²（q₃ ∈ [0, ε]） | H₃₃ > 0。W₃ の q₃ → 0 の極限を扱う |
| II | C₁₂ = T₁₂/(q₁q₂)（q₃ = 0） | C₁₂ > 0。赤道面の中で軸の外に停留点がない |

範囲は第一八分体（鏡映の対称性）と閉球、形は主矩形。区分（軸の面、赤道、内部、縁）とセルの分け方は、V60 の計画（`calibration/V60/input/unpacked/v60/PLAN_V60.md`）と同じにする。

**Reader のコード（`GER2/geoenclosereader/tri*.py`）は読まないでください。** 式は上の出典の定義から自分で導きます。読んでよいのは、Reader の入出力の形（箱の書き方、結果の行の欄）だけです。

## 3. 核の要件（基準 v1.1 に従う）

1. **表示：** Reader とは別の表示を使う。候補は V56 の log-chord 座標（q̂ = q/|q| を軸に、ξ = q + ρω、ρ = √(1−|q|²)·e^τ）。ほかの表示でもよいが、選んだ理由を書く。
2. **丸め：** 外向きに丸める区間演算（binary64 なら nextafter など）。浮動小数点の環境を記録する。
3. **積分の剰余：** Gauss–Legendre などの近似値を、そのまま保証値に使わない。剰余の上界を証明して加えるか、セルごとの平均値形式で包む。剰余の証明は、監査の対象になるので文書にする。
4. **特異点と境界：** 縁（|q| → 1）と軸、接触に近いセルの扱いと根拠を書く。境界での値は、内部からの極限（REPORT.md の補題 0）として扱う。
5. **赤道の帯：** V62・V62-B で、Reader の包み方は赤道の帯で止まると分かった（`evidence/chat/2026-11-22/D_TRI_H33_TERMS_DIAG_V62B/CHAT_RESULT_V62B.md`）。急な帯が q₃ と一緒に動き、パラメータでの微分の包囲が膨らむためである。**新しい核の表示を選ぶときに、この問題を避けるように設計すること。** H₃₃ が q₃ について偶関数であることも使ってよい。
6. **速さ：** C で書く。並列はプロセスでもスレッドでもよいが、結果が並列の数で変わらないこと。
7. **速さは、式と格子の作りで稼ぐ。** 旧 v1.2 の診断（commit `5c1444ad`、`evidence/astra/2026-11-22/C_PORT_TRI4/`）で、Reader をそのまま 1 ビット一致で C に移しても、速さは 1.4〜2.0 倍にとどまった。時間の 9 割は、格子の上の区間の配列演算そのものに使われている。20 倍を得るには、演算の回数を減らす設計（急な帯にだけ細かい格子を置く、表示を変えて微分の包囲を狭くする、など）が要る。丸めは、演算ごとの nextafter の代わりに丸めの向きの切り替え（`fesetround`）を使ってもよい。和も、誤差の上界を加えるなら、正確な和でなくてよい。**Reader と 1 ビット一致させる必要はない**（試験 B は区間が交わることだけを求める）。
   - 注意：旧 v1.2 の作業をしたセッションは Reader のコードを読んでいる。v2.0 の核は、Reader のコードを読んでいない別のセッションで書くこと（旧 v1.2 の報告にも、そう書かれている）。

## 5. 本計算の計画（試験の後）

試験 A・B に合格したら、本計算の計画（`PLAN_PRODUCTION_I_II.md`）を書き、**流す前に chat の監査を受けて**ください。計画には次を含めます。

- 被覆：セル、区分、タイルの全部の一覧と、それが第一八分体 × 主矩形を覆うことの証明（整数の算術での検査）。
- 規則：分け方、格子、予算、止める条件。結果を見てから変えない。
- 台帳：葉ごとに、箱、量、包囲の両端、使った格子を記録する。**chat は、この台帳から種つきで葉を抜き取り、Reader で包み直して監査する**（交わり、符号の一致）。
