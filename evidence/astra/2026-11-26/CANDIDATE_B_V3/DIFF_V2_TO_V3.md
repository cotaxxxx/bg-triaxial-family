# 候補B｜v2 から v3 への差分

2026-11-26 JST · DIAGNOSTIC_ONLY

| 項目 | v2 | v3 |
|---|---|---|
| 出発点 | 四量の全域を処理 | 固定した v2 原本の符号・帯・辺・接続を読み、未決葉を処理 |
| 共有端点 | 二量を別々に包み、帯の傾きで比較 | $1-y$ を外した差を既存の形微分から包む。$b_p$ は和・差から共通帯の面を構成 |
| 軸の未決 | 深さ18で停止 | 既存帯を横断方向に広げる。残る葉は直接包囲 |
| $Z_2$ | 帯を追跡してから残りの形箱を評価 | 帯を再利用し、横断微分の一度の確認で複数葉を覆う。直接16・64・256セルで早期終了 |
| 予算 | 各量2,400万、計1億400万セル | 追加枠1,800万・2,200万・300万・200万、計5,010万セル |
| $Z_1\cap\partial_2$ | 傾き、グラフ接続、端点順序 | 固定の補助帯で同じ条件を再検査し、Krawczyk の真の包含・縮小率を併用 |
| 全域交差 | 帯の重なりによる各対の条件 | 全四曲線の被覆完了を前提に、すべての重なりを再列挙して判断 |
| 台帳検査 | v2 の素区間、木と帯、接続・交差 | その検査を原本に適用し、v3 の差、面、残余木、行列と全域比較を有理数で読み直す |

数値核 `src/candidate.c`、`src/interval.h`、`src/jets.h` は v2 とバイト一致。従って核のバイト差分は0。ビルド、ヘッダ照合、`engine.py`、v2 の入力も同じバイト列。旧検査を改名して `verify_v2.py` として同梱し、新しい運用は `run_candidate_b_v3.py`、`method_v3.py`、`verify_v3.py` に置いた。新しい固定値の出典は [PLAN.md](PLAN.md) と [V3_INPUTS.json](V3_INPUTS.json)。[v2 固定版](https://github.com/cotaxxxx/bg-triaxial-family/tree/bb50c85c1bff93e3e04b54c5cbd218dcb3768a96/evidence/astra/2026-11-26/CANDIDATE_B_V2)
