# Reader 0.6.0 プロフィール（実測、秒）

固定標本で最初に現れる各種類の根を N=64、NH=32、eager で同じプロセス内で2回評価した。種類ごとに最初に格子キャッシュを空にした。C の作成前に計測した値を示す。

|種類|キャッシュ|格子|区間配列|fsum|残り|計|
|---|---|---:|---:|---:|---:|---:|
|H33|空|1.626|0.811|0.006|0.032|2.475|
|H33|再利用|0.002|0.773|0.006|0.030|0.811|
|W3|空|1.087|0.266|0.003|0.012|1.368|
|W3|再利用|0.001|0.262|0.003|0.012|0.279|
|C12|空|1.185|0.636|0.005|0.027|1.853|
|C12|再利用|<0.001|0.621|0.005|0.075|0.702|

区分は関数の境界による。格子は tri4._grid の内側全部（mpmath、配列の生成、呼び出し時の端点再生成を含む）。区間配列は格子の外側で fiv.I の演算・生成メソッドに費やした排他的時間。fsum は I.fsum。残りは Python の分岐や有理数処理、これらのラッパーを通らない NumPy 操作などである。計装のオーバーヘッドを含み、CPU 命令別の比率ではない。生値は results12/profile.jsonl にある。

格子を再利用した時の区間配列の比率は順に95.3%、93.9%、88.5%。v1.2 では、この測定から格子上の被積分関数、dual/jet の配列演算、Horner 評価、平均値セルと総和を C の対象に選んだ。tri4.enclose の組み立てとスカラーのべき乗は元の Python のままである。格子の構築には元の40桁の mpmath と元の有理数を使う。初回の格子生成費用はベンチの時間にも含める。

格子と C の間では、値を共通の binary64 配列またはスカラーで渡す。球面格子は shape=(N,2N) で、三角関数の区間8組、積分重み5組がそれぞれ下端と上端を持つ。Hessian 用は (NH,2NH)。平坦化するときは C 順で、元の全セルを順に積算する。格子全体にわたる除算の符号チェックも保存する。
