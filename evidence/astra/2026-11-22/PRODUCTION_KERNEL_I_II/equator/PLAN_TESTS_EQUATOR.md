# E1–E4 事前登録（監査待ち）

2026-11-22、DIAGNOSTIC_ONLY。指示は c25ba7bc2b044356896e948f6201f8ade77eb06d の v2.0・追補 v2.1。今回は設計と計画の登録のみ。chat の監査記録を確認してから試験を始める。研究 PC の E4 は Dig の運用指示 §2 にある両計画の監査条件にも従う。Fable 5.2 の査読結果、chat の監査と Judge の判断を区別して記録する。

## 1　共通の評価規則

- C で MPFR 128 ビット、RNDD/RNDU の包含演算。有限個の三角関数の極値は範囲中で ±1 を含める。入力有理数を区間に外向き変換する。二乗の零またぎ、無限大・NaN、空区間を独立に検査する。コンパイラ・MPFR/GMP の版、CPU、丸め、精度、ビルドフラグ、並列数、入力と出力の SHA-256 を保存する。fast-math 不使用。各組は単一スレッド、総和はセルの固定辞書順で行い、並列度で算術の順序を変えない。
- 角度積分は DERIVATION §§2–3。初期区画は緯度4等分・方位8等分の32矩形（接触の補集合も同様）。分割は一枚を両方向の中点で四分割する。面積込み直接包囲と剰余込み二節点公式の共通部分を使う。必要な積分ごとに、寄与区間の幅が最大のセルを優先し、同値なら初期の緯度→方位の順、次に四分木の道順（左下、左上、右下、右上）を固定する。比較は有限区間幅を上向きに計算した MPFR 数で行い、上界無限のセルを先頭とする。セルの選択に用いる幅に証明上の仮定はない。
- 各積分の角度葉数 128、512、2048 以下で到達できる最後の四分割段階（128,512,2048 枚、初期 32 から 3 枚ずつ増加）を段階 1–3 とする。一つのパラメータ箱では各段階について全積分を同じ上限まで計算する。内部では H の直接式、中心式、偶関数式を交差させる。H(0) の項は他の四変数の全箱で積分し、Hₐₐ は a=0 から上端までの全箱で積分する。外側に膨らむ箱の内部判定はこの拡大後にも行う。Hₐ を測るときは直接式と a[Hₐₐ] を用いる。点で零幅の方向に掛ける項の計算は省ける。各段階の有効な包囲も相互に交差させる。独立な有限包囲が交わらない場合は直ちに INCONSISTENT。
- E1–E3 は段階3の有限な端点を返す。診断を自明に通す全実数区間、Reader の区間によるクリップ、参照値を使った調整は不可。非有限や資源不足は未完とする。E4 は各段階で正下端が得られればその箱を葉にする。全ての段階で上端≤0 となるのを待つ必要はない。有効な包囲一つで上端≤0 が出たら NONPOSITIVE として保全、chat・Judge に報告。有限だが零を含む箱は次段階または二分割へ送る。E4 のパラメータ分割は根幅に対する現在幅の最大比の方向（同率は s,t,q₁,q₂,a の順）。深さ優先で下半分を先に処理する。最大深さ 40、打ち切った非空の箱は UNRESOLVED。接触判定の事前位置分割では q の三方向だけの最大比を使う。
- 一つの「評価」は一つのパラメータ箱を一つの角度段階で完全に評価した回数とする。同じ箱を段階を変えて再評価した分も数える。別欄にパラメータ箱の異なり数、求積点・パネルの回数、葉と未処理の数を残す。時計による打ち切りは壁時計時間依存なので、BUDGET の途中計数は同じ機械でもずれ得る。確定した葉の包囲・木の順序を再現可能にする。

## 2　E1　既知の試験箱

順序 (s,t,q₁,q₂,a)。箱は [53/20,53/20+11/160] × [43/8,43/8+5/32] × [27/32,27/32+1/64] × [7/32,7/32+1/128] × [0,1/1024]。主測定は全五変数を有理中点に固定した Hₐ=∂³E/∂a³（a=1/2048）。同じ規則で全箱の Hₐ も測る。中心・全箱それぞれについて直接式と偶関数式、共通部分の [lo,hi] と hi−lo を段階ごとに保存する。比較欄に grid_test_box.md の Reader B₄ の幅 91.6（N=256）、19.2（N=512）を原表記で掲載する。原報告で入力範囲の詳細が特定できない比較は「中心／全箱対応未照合」とし、H の幅と Hₐ の幅を混同しない。a=0 の対称性だけの零幅を主測定にしない。幅の改善量は合否条件にしない。

## 3　E2　72 点の高精度参照

- c25ba7b の V62/out_A.jsonl（正確なパスは DESIGN、Git blob 33040be992cfdb64d7d148a6c8babbcd316279e1）の group=A、i=0,…,71、status=OK を使用する。p の五有理数をそのまま読む。4 タイル (0,0),(1,3),(2,5),(3,7) の中心 × q₁∈{27/32,55/64,7/8} × q₂∈{7/32,15/64,1/4} × a∈{0,1/32} の直積と重複込みで照合する。B、C 群を混ぜない。
- 独立参照は元の固定 ξ の定義の H を mpmath、10進80桁と110桁の二回で適応積分する。例えば入力の定義式を ξ 固定で二階微分した値を用いる。設計側の座標変換・区間 Taylor 核を再利用しない。角度変数は z=sinλ、φ、面積 cosλ、分割点は λ=−π/2,asin(a),π/2、φ は四象限。各部分を tanh-sinh の次数を増やして積分する。角度の正則端 γ=1 は 8–9 の有限な解析値で扱う。一次・二次微分は γ=1 の F′=−2、F″=2/3（9 の n=2 から）を含む。相対でなく絶対差 <10⁻⁵⁵ を満たすまで両精度で最大次数 12。満たさなければ REFERENCE_UNRESOLVED。二回の一致は参照の数値診断で、剰余の証明にはしない。
- 高精度の参照の値（110桁計算値を少なくとも60有効桁で保存し元精度でも比較）を Astra 区間が含むことを全72点で要求する。一つでも外れたら E2 FAIL として記録し E4 に進まない。点の真値について保証を与えるのは区間計算側である。

- 根の五対は V60/samples_v60.json の同一キー・層・区分・kind の有理端点と照合する。形・位置を丸めて箱を縮めない。状態は COVERED / BUDGET / UNRESOLVED / NONPOSITIVE / INCONSISTENT / PARTIAL を区別する。各組の状態、完走有無、葉、評価、残りの箱、最大深さ、最小下端、CPU秒・壁時計秒・換算秒、最大メモリ、葉台帳の SHA-256 を出力する。
- 予算は各組につき **chat 作業機換算 14,400 秒**、研究 PC の単調壁時計で B=14,400×median(bench_PC)/45.1 秒。新核自身の高速化をベンチ換算に混ぜない。実装前に固定する運用は八組を各一ワーカー、八本同時。同じ八本同時負荷・コールド開始で V60 の参照 bench 二評価を監査側／Dig の運用担当が手順に従い一回測る。八秒数の中央二つの算術平均を median とする。単体の値、基準 45.1、B、参照区間の照合結果と機械を記録。比較の単位を合わせるため同時数は bench と E4 で共通、過去の r を転用しない。運用側の参照 bench から Astra は個別の結果データだけを受け取り、Reader のソース・束を開かない。八本がメモリ・運用制約に合わない場合は実行前に停止し、監査済み改訂を待つ。
- 各組の時計を根評価の直前に開始。締切到達で新たな仕事の受付を止め、未確定の途中評価は破棄し、該当箱を未処理台帳に戻す。途中評価数と超過した保存時間を別記する。根の被覆と全葉の厳密正値を検査できたときだけ完走とする。Dig の手順に従い、入力照合、PC の単独稼働、一回限りの実行、障害時 PARTIAL、出力 SHA-256 の照合、開始・終了・登録の記録を残す。
- 一組以上完走なら v2.0 の本計算計画への組込み候補とする。全組未完なら計数を報告して Judge の判断を待つ。全主矩形の検証実績、v2.0 の A–D の合否、20倍の性能は別の計画で検証する。

監査時の照合順は (1) E1–E4 の量・条件、(2) 葉選択と予算の固定、(3) 禁止物を介さない試料受渡し、(4) DERIVATION の §2–4 の剰余・接触上界。今回の SHA256SUMS.txt は三文書に対するもの。実行結果と表は監査後に別 commit で追加する。
