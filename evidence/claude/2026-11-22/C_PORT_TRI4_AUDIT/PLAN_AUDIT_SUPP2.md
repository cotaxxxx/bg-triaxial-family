# 追加の計画 2（実行前に固定）｜本番の走らせ方をなぞる

2026-11-22 ／ Claude Code ／ **DIAGNOSTIC_ONLY**

これまでの 133 件は、箱を 1 個ずつ独立に包んだ。本番（V63-A）の走らせ方は、それと 3 点で違う。grade が 4 まで上がる。N は 256 から始まり 512 まで上がる。grade が 0 でない格子は箱の q₃ の中心ごとに作り直され、格子の置き場は 4 個を超えると空にされる。格子を作る部分は mpmath のままで、C に移っていない。したがって、暖めた格子での速さは本番の速さを表さないおそれがある。これを測る。

## 入力

chat の本番用の束 `evidence/chat/2026-11-22/D_TRI_V63A_GRID/V63A_PC_BUNDLE.tar.gz`（SHA-256 `71bba593815ad696db657d5fa707c16f0697a5b5ea72d78cb83d4608730d7513`、`origin/evidence/triaxial-chat` の `daad309`）の中の `v63a/samples_v63a.json`（9 件：H33 が 8 件、W3 が 1 件）。束は読むだけで、書き換えない。

## 手順

`replay_v63a.py` は、束の `v63a/run_v63a.py` の細分の規則をそのまま写したものである。変えたのは 2 点だけである。

1. 時間の予算の代わりに、1 件あたりの包囲の回数が 4 回に達したら止める（時間で止めると、速い版ほど先へ進み、比べられない）。
2. 包囲を呼ぶ直前に、同じ引数で格子を先に作らせ、格子の時間と包囲の時間を別に測る。格子の置き場を空にする条件と順序は元と同じである。

包囲のたびに、箱、N、grade、区間の両端のビット、`enclose.last` の全項目、格子を新しく作ったか、2 つの時間を記録する。

これを 3 つの版で走らせる：Python 版（Reader 0.6.0）、Astra の C 版、テープ版（`tape/`）。どの版も 3 本を同時に走らせる（9 件を 3 つに分ける）。スレッドは 1 本に固定する。

## 判定

時間を除く全項目が 3 つの版で一致するかを見る。1 項目でも違えば、不一致としてそのまま報告する。速さは、格子の時間と包囲の時間に分けて表にする。速さは参考であり、判定に使わない。

## 計画の外

束の本番の計算そのもの（1 件 4 時間の予算）は走らせない。研究用 PC は使わない。採否は書かない。
